# Implementation notes

## 2026-10-12 — DMNC-1561 staging plate: replace via search/speech, scan to add

Observations and judgment calls made while executing plan "Work item 2" (to-change-a-couple-curried-eclipse.md):

- **`searchMealEntries` is file-private.** It lives in `private extension DataStore` in `FavoriteStore.swift`, so `FoodCorrectionStore` cannot call it. Added a thin internal wrapper `searchMealEntriesForPlate(matching:limit:)` in the same file (the `clinicGlucoseStatistics` wrapper precedent) instead of widening the original's access. `.searchPlateItems` zips `searchPersonalFoods` + that wrapper (each half `.catch`es to `[]`) into one `PlateItemSearchResults(query:personalFoods:mealEntries:)`.
- **Item-scoped AI state shape.** Plan said "transient `foodItemAnalysisResult`/`Loading`". Implemented as `foodItemAnalysisLoadingItemID: UUID?`, `foodItemAnalysisResult: FoodItemAnalysisResult?` (carries a fresh `id` per landing so the plate's `onChange` fires for a second answer on the same row), `foodItemAnalysisError: FoodItemAnalysisError?` (row-scoped), plus `.setFoodItemAnalysisError(itemID:error:)` and `.resetFoodItemAnalysis`. The reducer sets loading on `.analyzeFoodItem`, so the middleware's consent refusal emits an error action rather than `Empty` (which would strand the row's spinner).
- **REPLACE trigger is an icon button** (magnifier, 44pt, `accessibilityLabel("Replace item")`) beside the existing barcode icon in the Name row, not a text button — a text label there squeezes the name field on small phones. It tints amber while its panel is open. The panel itself is titled "REPLACE ITEM". Swap if the word is wanted on the button.
- **Portion fields on replacement.** When the new source knows a serving, `baseServingG/currentAmountG/carbsPerG` are set from it (barcode/AI paths, same as the existing rescan path). When it does not (all history candidates today), they are CLEARED rather than kept: they described the old food, and a stale `carbsPerG` would rescale the new carbs on the next amount edit.
- **Provenance at populate time.** `populateStagedItems` sets `source = .history` for relog, `.ai` otherwise — the plate cannot tell a whole-plate barcode result from an AI one. Provenance never feeds the carb math or corrections, so this is display/debug data only. `replaceWithFollowUpResult` also sets `originalIndex` (the follow-up result becomes `foodAnalysisResult`, i.e. the new correction baseline).
- **Corrections matcher** extracted to `Library/Content/StagingPlateCorrections.swift` (`compute(original:staged:)`); duplicate or out-of-range `originalIndex` is treated as an addition, and every unclaimed original is a deletion. Output for an unedited, un-reordered plate is identical to the old positional matcher.
- **Clarify mic** keeps its item-names-only contextual strings; it gained `stopToken: dictationStopToken`. The REPLACE panel's mic uses the new plate-local `replaceContextualStrings` (items + favourites + recents, cap 100) — `UnifiedFoodEntryView.foodContextualStrings` was copied, not moved.
- **DB search threshold** is `FoodHistorySearchModel.minQueryLength` (3), same as the Log Meal sheet; below that the in-memory ranker answers alone. There is no "searching" spinner in the panel — stale/absent DB hits just mean the in-memory candidates show.
- **"Add Item" row** now holds two `.plain`-styled buttons (Add Item / Scan Item) — a default-style Form row would fire both on any tap.
