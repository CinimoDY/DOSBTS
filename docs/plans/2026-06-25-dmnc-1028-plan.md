# Hypo-Filtered Entry Sheet Escape Hatch — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Guarantee a user mid-hypo can always log carbs through the MEAL button, even with zero hypo favourites *and* zero recents, by adding a persistent "LOG OTHER FOOD" manual-entry escape row to the hypo-filtered food entry sheet.

**Architecture:** Add a tiny pure decision model (`HypoFilteredEntryModel`) inline in `UnifiedFoodEntryView.swift` — mirroring the existing `GlucoseStatusBarModel` pattern — that derives section visibility (`showsEmptyHypoMessage`, `showsEscapeRow`) from raw inputs. The view consumes it; the escape row pushes the existing `AddMealView` (manual carb entry) via `NavigationLink`. The treatment cycle is purely glucose-driven, so a plain `.addMealEntry` from the escape row treats the hypo correctly with no extra wiring.

**Tech Stack:** SwiftUI, Redux-like Store/Action/Reducer, Swift Testing (`@Test`/`#expect`), GRDB (no schema change here).

## Global Constraints

- **No force unwrapping** (`!`) — use guard/let, optional chaining, nil coalescing.
- **`DOSTypography` members only** — no `headline`/`title`; available members include `caption`, `bodySmall`, `body`.
- **CGA amber theme** — text colours via `AmberTheme` tokens (`amber`, `amberDark`, `cgaGreen`); no real white.
- **`NavigationStack` not `NavigationView`** — `navigationDestination`/`NavigationLink` push is silently ignored inside legacy `NavigationView`; the host view already uses `NavigationStack`.
- **No nested `.sheet` inside a sheet** — the escape row pushes (`NavigationLink`), it does not present a sheet.
- **Pure models for view-logic invariants** — follow the `GlucoseStatusBarModel` precedent: the no-dead-end guarantee must be a pinned, regression-protected unit test, not a view-only behaviour.
- **New test files are NOT auto-synced** — a new file under `DOSBTSTests/` requires four manual `project.pbxproj` edits (PBXBuildFile, PBXFileReference, PBXGroup child, PBXSourcesBuildPhase). Exact IDs/anchors given in Task 1.
- **CHANGELOG** — this is a user-visible change; add an `[Unreleased]` entry in the same PR.

## Problem Frame

During a treatment cycle (Rule of 15 hypo workflow), the persistent bottom-bar MEAL button routes to the **hypo-filtered** food entry sheet everywhere (R8, shipped Build 99). The unfiltered Overview button row is gone.

Current filtered-sheet contents (`UnifiedFoodEntryView(filterToHypoTreatments: true)`):

- **Favourites:** `store.state.favoriteFoodValues.filter(\.isHypoTreatment)`. If empty → a static `"NO HYPO TREATMENTS CONFIGURED"` message (`UnifiedFoodEntryView.swift:35–43`).
- **Recents:** shown **unfiltered**, but if the user has never logged a meal → `"Log your first meal to see recents here"` (`UnifiedFoodEntryView.swift:204–213`).
- **Actions section** (MANUAL / SCAN / PHOTO / ASK AI): **suppressed** in filtered mode (`if !filterToHypoTreatments`, `UnifiedFoodEntryView.swift:51`).
- **Gear → `FavoriteManagementView`:** cannot create a favourite from scratch — it only lists existing favourites and tells the user to "Swipe left on a recent meal to add it" (`UnifiedFoodEntryView.swift:414–415`). With zero recents there is nothing to swipe.

**The dead-end:** a user with zero hypo favourites **and** zero recents has *no* path to log any carbs from the MEAL button mid-hypo. Defaults seed two hypo favourites ("Dextrose tabs" 15g, "Juice box" 25g — `FavoriteStore.swift:132–156`, plus a migration seed at `:179–209`), so reaching the lockout requires deliberate deletion of both — but it is a real safety gap flagged by the adversarial reviewer (PR #52 Known Residuals) and deserves a deterministic fix.

**Why a plain `.addMealEntry` is sufficient (verified):** `TreatmentCycleMiddleware` reacts only to `.logHypoTreatment`, `.addSensorGlucose` (recheck on the next reading), and lifecycle actions. It does **not** consult carb/meal data and does **not** depend on `.logFavoriteFood` (which only bumps a `lastUsed` sort heuristic — `FavoriteStore.swift:64–69`, no reducer). So a manual meal entry that skips `.logFavoriteFood` is fully valid for treating a hypo; the countdown/recheck proceeds on glucose alone.

## Design Decision (KTDs)

The issue names two candidate fixes. This plan chooses Option A.

### KTD-1: Add a focused "LOG OTHER FOOD" escape row (Option A) — **chosen**

Reject **Option B (un-suppress the full `actionsSection` in filtered mode)** because that section contains PHOTO and ASK AI — slow, network-dependent, AI-consent-gated, cognitively heavy flows that are contraindicated mid-hypo (the filtered sheet deliberately strips them; hypo favourites are even 1-tap-direct-log with no hold gesture, R4/KTD-7). Un-suppressing it re-clutters the sheet and re-introduces the exact heavyweight surfaces R8 removed.

Option A adds a single, low-emphasis row that pushes `AddMealView` — the fastest path to record "I ate ~15g": type a description + carbs, done. It is the same manual-entry destination as the existing MANUAL action, so there is one mental model and no new entry view.

### KTD-2: The escape row is **always present in filtered mode**, not only when empty

Driven by the pure model's `showsEscapeRow == filterToHypoTreatments`. Always-on is simpler (no conditional coupling to favourites/recents counts), removes the dead-end in *every* filtered state, and also serves the adjacent need "I want to log something not in my hypo list." The trade-off — one extra low-priority row when the user *does* have good hypo favourites — is negligible and the row sits last, below QUICK and RECENT.

### KTD-3: Reuse `AddMealView` via a DRY `manualEntryLink(...)` helper

Factor the existing MANUAL `NavigationLink` body (`UnifiedFoodEntryView.swift:250–266`) into a private `@ViewBuilder func manualEntryLink(icon:title:)` used by both the unfiltered `actionsSection` MANUAL row and the new filtered escape row. The two never render simultaneously (one is `!filterToHypoTreatments`, the other `filterToHypoTreatments`), but sharing one helper keeps the `.addMealEntry` dispatch + highlight + dismiss logic in a single place.

### KTD-4: Pin the no-dead-end guarantee with a pure model

Extract `HypoFilteredEntryModel` (inline at the top of `UnifiedFoodEntryView.swift`, mirroring `GlucoseStatusBarModel`'s placement inside `GlucoseStatusBar.swift`). The view's structural `if` branches read from it; `HypoFilteredEntryTests.swift` pins that filtered + zero hypo favourites always yields `showsEscapeRow == true`. A future change that made the escape row conditional would have to change the model and break the test — the safety invariant is regression-protected.

/// Pure mapping of the hypo-filtered food entry sheet's structural decisions.
/// During a treatment cycle the MEAL button routes here (R8); a user with
/// zero hypo favourites and zero recents must still have a way to log carbs,
/// so the escape row is always present in filtered mode (DMNC-1028). The view
/// renders this; `HypoFilteredEntryModelTests` pins the no-dead-end guarantee.
struct HypoFilteredEntryModel: Equatable {
    /// "NO HYPO TREATMENTS CONFIGURED" — shown when filtering yields no chips.
    let showsEmptyHypoMessage: Bool
    /// "LOG OTHER FOOD" manual-entry escape row.
    let showsEscapeRow: Bool

    static func make(hypoFavoriteCount: Int, filterToHypoTreatments: Bool) -> HypoFilteredEntryModel {
        HypoFilteredEntryModel(
            showsEmptyHypoMessage: filterToHypoTreatments && hypoFavoriteCount == 0,
            showsEscapeRow: filterToHypoTreatments
        )
    }
}
```

    /// Shared "type a meal + carbs" destination. Used by both the unfiltered
    /// actions section (MANUAL) and the filtered escape row (LOG OTHER FOOD).
    @ViewBuilder
    private func manualEntryLink(icon: String, title: String) -> some View {
        NavigationLink {
            AddMealView { time, description, carbs in
                let mealEntry = MealEntry(timestamp: time, mealDescription: description, carbsGrams: carbs)
                store.dispatch(.addMealEntry(mealEntryValues: [mealEntry]))
                addedHighlighter.flash(mealEntry.id)
                dismiss()
            }
            .navigationBarHidden(true)
        } label: {
            HStack {
                Image(systemName: icon)
                    .font(DOSTypography.caption)
                Text(title)
                    .font(DOSTypography.bodySmall)
            }
            .foregroundColor(AmberTheme.amber)
        }
        .accessibilityLabel("Log a meal manually by typing carbs")
    }
```
